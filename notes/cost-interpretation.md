# Cost interpretation

The ledger separates actual investigation work from per-policy deployment paths.
Every acquisition attempt, both histories, all counterfactual candidate endpoints,
all observations and final-evaluation calls remain charged to investigation.
The development continuation-equivalence experiment adds 192 updates, and reload
audits have their own generation/token/time ledger. No failed acquisition is free.

A deployed selected history pays for one acquisition and one 192-update first
revision. A fixed second revision costs 192 updates. The attempted prefix pipeline
costs 216 because saved optimizer continuation was verified; no restart or third
training run is charged. Sparse/full endpoint validation trains both candidates
(384 updates) and retains the selected endpoint. Sparse uses eight observations
per candidate; full-condition validation uses 32 per candidate. The final suite
is never a selection panel. Its use costs are also listed as an illustrative
192-order deployment workload, without double-counting them in investigation.

The newly fitted observational selectors reduce to constant Bridged before
assessment. A competent deployed implementation can simplify them to the developed
constant and omit all observations and prefix training. The nominal 16-call
pre-observation and 32-call/216-update prefix costs describe the investigated
pipelines, not a necessary expense for their actual constant decision. No useful
information purchase is established by executing them.

The example table is constructed from checked examples already supplied to the
neural route. It scans 64 original records and 64 correction records per revision,
maintains 16 condition keys and overwrites two keys per revision. It does not need
to reread unchanged rehearsal labels. Investigator-supplied entity invariance,
field addressing, correction authority and programmer effort are disclosed.
Table-use timing includes response checking; nanosecond-scale precision does not
make these timings a hardware benchmark. Model use includes token generation.
No dollar conversion, electricity estimate or human-effort price is invented.

Historical S2 evidence is prior development information, not free fresh labels.
Its pinned state/support phase reports 4,096 updates, 4,736 generations, 366,020
training input tokens, 32,768 loss tokens, 389,728 inference prompt tokens and
37,823 completion tokens; 2,212.07 active seconds, plus 221 audit probes/127.07
seconds. It additionally reused seed 401's earlier 256-update acquisition and
two 192-update first revisions. Those historical costs are not newly incurred or
added to this study's actual local-run ledger. Provenance: S2
3e71eb5f146e6493c60cef26d15d86dedd2249fb,
evidence/state-support-phase-audit/report.json and FINDINGS-STATE-SUPPORT.md.
The match-history rule uses that retrospective evidence; newly fitted controls
use only this study's seed 601 endpoints. No claim is made that one tiny new
calibration set exhausts what could be learned from all historical material.

Training, generation and wall time are separate native measurements. Checkpoint
bytes include optimizer snapshots in this study. All model runs check the same
base-model hash, log passive resource checks, and report observed peak MLX memory.
Assistant orchestration, programming, source inspection and investigation setup
are not assigned fabricated zero-cost or dollar estimates.
